# Security

## Reporting a vulnerability

Use GitHub's [private vulnerability reporting](https://github.com/matt-pasek/usva/security/advisories/new)
rather than the public issue tracker. That keeps the report private until there is something to
update to.

Include what you did, what happened, and which package and version you were on. A reproduction is
worth more than a description.

This is a solo project, so expect a first response within a week rather than within a day.

## Scope

usva. is a client-side component library. It has no server, no database, and it never handles
credentials, so the realistic surface is narrow. Things worth reporting:

- A component rendering unescaped user input into the DOM.
- `dangerouslySetInnerHTML`, or anything equivalent, reachable from a public prop.
- A supply-chain problem in what the packages depend on.
- The CLI writing files outside the project directory.

Out of scope: anything about the docs site's third-party hosting, and reports generated by a scanner
against a dependency that is not reachable from the published entry points. Say which entry point
reaches it and it is back in scope.

## Supported versions

The latest 1.x. Fixes land forward on the current minor rather than being backported to earlier
ones, and a breaking change waits for a major.
